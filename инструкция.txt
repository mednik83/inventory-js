Проект:
Inventory App — учебное fullstack-приложение для учёта оборудования.

Цель проекта:
Сделать нормальное портфолио-приложение для учёта оборудования:

Зоны ответственности frontend:

api.js:
- Только общение с backend через fetch.
- Не должен содержать document.querySelector.
- Не должен менять DOM.
- Не должен хранить состояние.
- Примеры функций:
  - equipmentApi.getAll()
  - equipmentApi.create()
  - equipmentApi.update()
  - equipmentApi.writeOff()
  - equipmentApi.forceDelete()
  - equipmentApi.getByUuid()
  - equipmentApi.getQr()
  - roomApi.getAll()
  - roomApi.create()
  - roomApi.update()
  - roomApi.delete()

state.js:
- Хранит текущее состояние приложения.
- Например:
  - equipments
  - rooms
  - filters
  - editingEquipmentId
  - selectedEquipment
- Не должен делать fetch.
- Не должен менять DOM.

dom.js:
- Хранит ссылки на DOM-элементы.
- Например:
  - equipmentList
  - equipmentForm
  - searchInput
  - roomFilterSelect
  - statusFilterSelect
  - showWrittenOffCheckbox
  - qrContainer

render.js:
- Только вставляет готовые компоненты в DOM.
- Не должен делать fetch.
- Не должен содержать бизнес-логику.
- Примеры:
  - renderEquipments(equipments)
  - renderRooms(rooms)
  - renderQr(svg)

handlers.js:
- Обработчики действий пользователя.
- Может вызывать api.js, state.js и render.js.
- Это слой-координатор.
- Примеры:
  - handleEquipmentSubmit()
  - handleEquipmentListClick()
  - loadEquipments()
  - setupEquipmentHandlers()

components/:
- Маленькие функции, которые создают части интерфейса.
- Компоненты не должны делать fetch.
- Компоненты не должны менять глобальное состояние.
- Компоненты не должны сами решать бизнес-логику.
- Компонент получает данные и возвращает DOM-элемент.

Пример правильного потока данных:
Пользователь нажал кнопку
→ handler
→ api request
→ обновили state
→ render

Пример плохого подхода:
Кнопка
→ fetch
→ innerHTML
→ querySelector
→ ещё fetch
→ изменение переменных
→ alert
→ кусочная отрисовка

Так делать нельзя, потому что frontend превращается в кашу.

Компонентный подход:
На vanilla JS компоненты — это не React-компоненты, а функции, которые создают DOM.

Пример:
- EquipmentCard.js создаёт одну карточку оборудования.
- EquipmentList.js создаёт список карточек.
- FiltersPanel.js создаёт панель фильтров.
- QrBlock.js создаёт блок QR.
- EmptyState.js создаёт пустое состояние.

Не надо делать слишком мелкие компоненты вроде:
- WriteOffButton.js
- DeleteButton.js
- EquipmentTitle.js

Для текущего проекта это перебор.

Лучше делать компоненты среднего размера:
- EquipmentCard
- EquipmentList
- EquipmentForm
- FiltersPanel
- QrBlock
- RoomSelect

Для событий лучше использовать data-action:
- data-action="edit"
- data-action="qr"
- data-action="write-off"
- data-action="force-delete"

И один обработчик на список:
equipmentList.addEventListener("click", handleEquipmentListClick)

Важно:
Если используются ES modules в браузере, в index.html нужно подключать main.js так:

<script type="module" src="./src/main.js"></script>

Импорты должны быть только на верхнем уровне файла:

Правильно:
import { equipmentApi } from "./api.js";

Неправильно:
function init() {
  import { equipmentApi } from "./api.js";
}

В браузерных import-путях нужно писать расширение .js:

Правильно:
import { dom } from "./dom.js";

Неправильно:
import { dom } from "./dom";
